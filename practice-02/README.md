| № | Прогноз до запуска | Фактический результат | Причина |

| 1 | `sum(2, 3)` даёт `5`; `sum("2", 3)` даёт строку `"23"` | `5` и `23` | Оператор `+` с числами складывает, а если один операнд строка, то выполняет конкатенацию. Функция не преобразует типы сама. |

| 4 | `7`, `false`, `true` | `7`, `false`, `true` | Spread создаёт новый массив (`products !== copy`), но вложенный объект остаётся общим (копирование поверхностное). |

## 4. Модель данных и функции

Задача — объект `{ id, title, completed, priority }`.

| Поле | Правило |
|---|---|
| `id` | Число, `Number.isSafeInteger(id)` и `id > 0`; строки не преобразуются; уникален в списке (проверяется в `addTask`). |
| `title` | Строка; после `trim()` длина от 1 до 100; сохраняется очищенная строка, внутренние пробелы не меняются. |
| `completed` | Булево значение; у новой задачи всегда `false`. |
| `priority` | Строго `"low"`, `"medium"` или `"high"`; по умолчанию `"medium"` (только для пропущенного аргумента или `undefined`). |

**Распределение ответственности:**

- `src/data.js` — только данные: `demoTasks`, `variantNumber`, `variantTasks`.
- `src/task-service.js` — вся прикладная логика (девять экспортируемых функций и небольшие внутренние функции проверки). Нет `console.log`, DOM и глобального изменяемого списка, данные только через аргументы.
- `src/main.js` — импорт, последовательность действий, вывод и обработка отказов.
- `checks.js` — готовые проверки (35) и три собственных случая.

**Результаты функций:**

| Функция | При успехе | При ошибке |
|---|---|---|
| `createTask` | `{ ok: true, task }` | `{ ok: false, error }` |
| `findTaskById` | найденный объект (не копия) | `undefined` |
| `getPendingTasks` | новый массив невыполненных | — (ошибок нет) |
| `getTaskTitles` | новый массив названий | — |
| `getTaskStats` | `{ total, completed, pending, progress }` | — |
| `addTask`, `setTaskCompleted`, `renameTask`, `removeTask` | `{ ok: true, tasks: новый массив }` | `{ ok: false, error }`, входные данные не изменены |

**Почему id не равен индексу:** список меняется (удаление, добавление), а идентификатор должен остаться прежним. В `demoTasks` задача с `id = 4` лежит под индексом 1. Если искать по индексу, после удаления записи найдётся не та задача.  
**Почему getTaskStats возвращает число, а не строку с процентом:** число можно дальше сравнивать и вычислять. Строка `"50.0%"` годится только для вывода. Округление `toFixed(1)` выполняется при отображении в `main.js`.  
**Какие объекты копируются при изменении задачи:** создаётся новый массив (`map`, `filter` или spread) и новый объект выбранной задачи (`{ ...task, поле }`). Невыбранные записи используются повторно, их менять нельзя.
